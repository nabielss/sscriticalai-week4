## 1. Urutan migration: sesuai

Urutan `up()` di `run_up` sama dengan baris 2-7 challenge, yaitu ADD COLUMN, UPDATE, CREATE INDEX, RENAME, lalu ADD CONSTRAINT. `down()` juga sama dengan baris 11-12, yaitu DROP COLUMN lalu RENAME balik. Isinya verbatim.

Satu deviasi yang diakui script sendiri: SQL dibungkus `BEGIN/COMMIT`, sedangkan aslinya lima `db.query` terpisah. Ini tidak mengubah temuan kompatibilitas dan rollback. Tapi harness ini memang tidak menguji lock atau waktu, jadi pembungkus tersebut tidak punya efek yang terukur di sini.

## 2. Transaksi

- `ON_ERROR_STOP=1` dengan `BEGIN/COMMIT` di heredoc benar. Kalau satu statement gagal, psql berhenti dan transaksi tidak ter-commit.
- Tidak ada pengaman terhadap target koneksi. `reset_fixture` menjalankan `DROP TABLE IF EXISTS invoices`. Di CI ini aman karena `PGHOST` diset ke service container. Tapi kalau script dijalankan lokal dengan `PG*` env yang menunjuk staging, tabel `invoices` akan terhapus. Usul guard di awal script:

```bash
[[ "${PGHOST:-}" =~ ^(127\.0\.0\.1|localhost)$ && "${PGDATABASE:-}" == week4 ]] \
  || { echo 'REFUSING: target must be loopback week4 database'; exit 3; }
```

## 3. Assertion `pg_indexes`

Assertion ini memeriksa dugaan yang menjadi koreksi atas baseline saya, bahwa `DROP COLUMN currency` ikut menghapus indexnya. Masalahnya:

- **Tidak ada positive control.** Hitungan 0 setelah `down()` hanya berarti sesuatu kalau sebelumnya terbukti 1. Tanpa itu, 0 bisa muncul karena index tidak pernah terbentuk atau filter salah. Tambahkan setelah `run_up` di `run_rollback`:

```bash
idx_before=$(psql_ci -Atc "SELECT count(*) FROM pg_indexes WHERE schemaname = current_schema() AND tablename = 'invoices' AND indexname = 'invoices_currency_idx';")
assert_eq "$idx_before" '1' 'currency_index_exists_after_up'
```

- **Label memuat kesimpulannya.** `currency_index_removed_with_column` sudah mengasumsikan hasilnya. Kalau index ternyata tertinggal, script exit 1 dan semua baris `EXPECTED_FINDING` berikutnya tidak tercetak. Lebih baik catat nilai yang diamati sebagai temuan, dan simpan assert hanya untuk positive control.
- **Tambahkan raw output**, misalnya `SELECT indexdef FROM pg_indexes WHERE tablename='invoices'` sebelum dan sesudah `down()`, supaya pembaca melihat keadaan index, bukan hanya hitungannya.
